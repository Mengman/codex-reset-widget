# Codex Reset Widget 需求文档

版本：1.0 候选。更新日期：2026 年 10 月 2 日。状态：当前需求基线，发布候选版等待最终验收。

本项目让用户在 Windows 桌面上快速查看下一次 Codex 重置、公告依据和历史记录。应用消费第三方整理好的结果，避免自行抓取和逐条分析 Tibo 的 X 内容。

## 1. 已确认需求与实现建议

用户已确认：Windows 桌面小工具；Windows 11 设计风格；兼容系统深浅色；视觉上包含重置公告板、Tibo 重置公告、历史重置日历；优先采用已经分析好的信息源。

窗口方案已确认：采用独立小窗口，供用户平时长期摆放在桌面上。窗口遵循普通应用的层级与“显示桌面”行为，允许被其他应用覆盖；Win+D 时可能被最小化或遮住，不要求继续可见。

用户已确认第一版支持展开态与紧凑态切换：展开态展示公告板、公告和日历；紧凑态保留标题栏与公告板，方便长期摆放。

发布形式已确认：第一版提供自带 .NET 运行时的 Windows 11 x64 便携 ZIP，解压后直接运行，无需另行安装 .NET 运行时；安装包作为后续候选。

以下为本轮文档采用的实现建议，后续可以调整：C# 与 WPF、Codex Resets 主数据源、托盘常驻、可选置顶、位置记忆。首次启动默认精简，之后恢复上次窗口状态；通知作为后续增强。

## 2. 产品边界

关注公告中的额度直接重置和限额重置券（可手动使用的重置机会）。公告重置与个人账户额度的自然恢复时间属于不同概念。应用不需要用户登录 OpenAI，不读取个人额度，不操作账户重置。

第一版不自建后端、不接入 X 登录、不逐条分析推文、不调用大模型预测日期。没有明确预定时间时，不用历史平均间隔制造倒计时。

## 3. 重置公告板

公告板位于顶部，拥有最高视觉优先级。内容包括状态、重置类型、预计日期与时间，以及可选倒计时；时区通过工具提示说明。

| 编号 | 情况 | 必须展示的行为 |
| --- | --- | --- |
| B01 | 有预定事件，时间有效且在未来 | 显示预计时间与倒计时；同时显示额度直接重置或限额重置券类型 |
| B02 | 有预定事件，但目标时间为空或无效 | 显示“重置已预告，具体时间待公布” |
| B03 | 只有观察或预测信号 | 显示“有重置信号，时间未定”；不生成精确倒计时 |
| B04 | 没有当前预告、有效观察信号或可回顾的预计时间 | 显示“下一次重置尚未公布”；可补充最近一次公告／观察记录 |
| B05 | 公告预计时间已到，尚无更新的预告取代它 | 显示“最近公告的预计重置时间”，大字号展示日期和时间，附“实际额度以 Codex 为准”；停止展示倒计时 |
| B06 | 数据源提供相应发生记录 | 仅在公告详情与历史中标注数据源记录；公告板不切换为“已完成”或“重置成功” |
| B07 | 更新失败但有缓存 | 保留原内容，单独标注缓存时间和更新失败 |
| B08 | 首次启动且没有数据 | 显示加载状态；失败后给出重试入口，不显示虚构日期 |

第一版自动读取并跟随用户电脑的系统时区，将接口时间转换后显示。公告预计时间、公告发布时间、日历日期及更新时间使用同一系统时区；原文中的时间文本保持原样。倒计时板块不显示“本地时间 · UTC”标签；时区与 UTC 偏移通过时间工具提示提供，偏移量按所展示事件时刻计算。超过一天的倒计时使用“天 + 时分秒”。

系统时区改变后无需重启，立即更新日期、时间、时区标识和日历分组；保留当前阅读事件与可见月份。倒计时按同一绝对时间计算，仅更改时区不会改变剩余时长。缺少时区偏移且接口合约未定义时区的时间不猜测，按时间无效处理。

倒计时注明“距公告预计时间”。到点后不显示完成图标、负数或停在零的倒计时，也不暗示正在核实个人账户。预告消失时保留原公告的预计时间并附状态待确认提示；新预告或时间更正可以替换显示。只有公告发布时间的记录不能被当作预计重置时间。

## 4. 重置公告

默认展示与公告板对应的推文，包括到点后回顾的公告；没有对应公告时，展示最近一条重置记录。包括作者、账号、发布时间、原文和外链。

- 原文按文本展示，支持换行；公告卡片固定 190 DIP，过长内容在正文区域滚动，作者和底行固定，不推动日历。第一版不自动翻译。
- 多条已收录的公告支持前后切换，不拉取无关动态。
- 点击日历中的历史事件，在此区域展示对应记录，通过公告左右按钮继续翻阅；标题始终为“重置公告”，不提供“返回最新”。历史选择不得改变顶部的当前倒计时。
- 有可核对 Tibo 来源的推文、回复和转推统一显示“公开公告”、Tibo、@thsottiaux 和 T 文字头像；内部保留 `observed` 来源类型。没有原文及归属证据时，不伪造 Tibo 作者或来源链接。
- `announced_at` 是公告或首次观察时间，不能标为实际执行时刻。
- 日期、原文和链接属于同一事件，避免组合出不同公告的内容。

## 5. 重置日历

提供月历视图，默认当月，周一为每周第一天。支持上月、下月和返回本月，日期按当前系统时区分组。

| 记录类型 | 标记 | 说明 |
| --- | --- | --- |
| 额度直接重置 `regular` | 蓝色圆点 | 直接重置当前额度的公开记录 |
| 限额重置券 `banked` | 琥珀色菱形 | 可手动使用的重置机会，不代表即时恢复 |
| 未来预告 | 空心标记并注明“预告” | 不计入已完成历史次数 |
| 无法识别的类型 | 中性标记 | 显示“类型待确认”，不默认归为额度直接重置 |

同一天多条记录可以显示数量；点击日期后列出当天所有事件。选中事件可查看原文和外链。颜色必须配合形状和文字，不能只靠颜色传递信息。

历史按 `announced_at` 转换到电脑当前系统时区后归档，栏目说明为“按公告／观察日期”。空白日期只表示当前数据源未收录，不能宣称当天没有发生重置。历史分页尚未加载完时显示加载状态。

## 6. Windows 桌面体验

- 展开态按“公告板、公告、日历”的顺序垂直排列；内容溢出时可滚动。
- 标题栏提供“收起为紧凑态”／“展开”按钮。紧凑态保留倒计时或无明确时间时的状态文案、重置类型、预计时间，以及必要的数据新鲜度提示；时区通过工具提示提供。
- 两种状态共用当前数据与刷新逻辑；切换后保留所选历史公告、日历月份和阅读位置。紧凑态可通过菜单查看来源与最后成功更新时间。
- 默认跟随系统应用主题；设置中支持固定浅色、固定深色。
- 系统主题变化时，无需重启即可切换；不能重置用户当前阅读的公告或日历月份。
- 建议支持拖动、可选置顶、位置记忆、托盘显示和显式退出。
- 托盘图标常驻；主窗口不出现在任务栏及 Alt+Tab 中。启动、最小化、隐藏与从托盘恢复均保持该行为。点击托盘图标恢复窗口并唤到前台。
- 图标按钮统一 16×16 DIP 图形、28×28 DIP 点击区域与 1.5 DIP 线宽，提供工具提示、键盘焦点及可访问名称。置顶通过空心倾斜／实心竖直图钉区分状态。
- 支持常用显示缩放；窗口恢复时不得落在已经断开的显示器之外。
- 数据来源链接和最后成功更新时间始终可找到。
- “…”菜单提供“关于 Codex Reset”，显示版本、https://github.com/Mengman、数据来源和 MIT 许可；使用蓝白计时器 Logo，不显示调试演示入口。

## 7. 优先级

P0：两个 API 接入、三大功能区、展开态与紧凑态切换、深浅色与跟随系统、手动与定时刷新、本地缓存、异常状态、数据署名。

开机启动选项已实现，默认关闭，用户明确启用后注册当前用户登录启动项。

P1：预告及到时通知、可配置提醒阈值、历史类型筛选。系统通知默认不启用。

后续候选：备用数据源适配器。切换数据源需要明确显示来源；共享同一个上游的网站不能视作独立确认。

## 8. 验收标准

1. 使用模拟的未来预定时间时，公告板正确显示倒计时；休眠恢复后立即按当前时间修正。
2. 缺少目标时间、仅有预测信号、数据过期和网络失败均有独立可理解的展示。
3. 到点后，展开态与紧凑态都改为展示最近公告的预计日期与时间，不标记完成；预告消失或数据源出现发生记录也不会让公告板宣称个人重置成功。
4. 公告原文、类型、发布时间和来源链接能对应同一事件。
5. 日历支持跨月、多事件、闰年和跨时区日期变化；选择历史记录不会修改当前预告。
6. 同一套数据在浅色和深色主题中信息一致；系统主题热切换后内容与位置不丢失。
7. 在 100%、150%、200% 缩放下，按钮、倒计时和日历可读、可操作；小屏幕使用滚动而非裁掉内容。
8. 首次离线有明确空状态；已有缓存时可读取；损坏缓存不会阻止应用启动。
9. 应用展示可点击的 Codex Resets 来源链接。
10. 展开态与紧凑态可通过鼠标和键盘切换；倒计时与异常状态保持一致，恢复展开后保留历史公告选择、日历月份和阅读位置。重启恢复上次窗口状态，切换及恢复时窗口保持在当前显示器工作区内。
11. 在未安装 .NET 运行时的干净 Windows 11 x64 环境中，解压完整发布包即可启动。设置、缓存和日志保存在 `%LocalAppData%/CodexResetWidget/`；退出应用后，将新版解压到新目录运行，可继续读取兼容的原有设置与缓存。
12. 同一接口时间在不同时区下显示正确的本地日期、时间和 UTC 偏移；覆盖跨日、跨月、夏令时和非整小时偏移。运行中修改系统时区无需重启，倒计时保持一致，日历重新分组；缺少偏移且合约未定义时区的值不会被当成本地时间使用。

## 9. 尚待实现阶段验证

- 运行时和依赖的具体版本、自带运行时的便携包体积，以及未来是否覆盖 ARM64。
- 实际 WPF 字体排版下的窗口尺寸和最小可用尺寸。
- API 长期更新延迟、预告更正与完成记录的关联方式。
- 当前采用的主源会解析自然语言时区；准确性不能仅凭一次接口实测保证。

## 语言

界面支持英语和简体中文。首次启动跟随 Windows 用户显示语言：简体及繁体中文均使用简体中文，其他语言使用英语。菜单可选择跟随系统、English 或简体中文；手动选择优先于系统语言，立即生效并保存，旧设置缺少语言字段时使用跟随系统。

界面文字、菜单、托盘、关于、状态提示和日期格式采用同一语言。切换保持公告、日历选择和阅读位置；原始推文不翻译。时区转换继续按电脑时区执行，与界面语言独立。
