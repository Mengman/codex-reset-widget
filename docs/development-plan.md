# Codex Reset Widget 开发计划

制定日期：2026 年 10 月 2 日。当前状态：M1、M2 已通过用户检查并提交；M3 及 V4 UI 修订已通过用户验收，实现提交为 `23ad0b3`；M4 尚未开始。交付与验证记录见 [M1 验收记录](milestones/m1-review.md) 、[M2 验收记录](milestones/m2-review.md) 、[M3 验收记录](milestones/m3-review.md) 和 [UI 修订验收](milestones/m3-ui-v4-review.md)。

第一版交付 Windows 11 x64 独立小窗口，包含公告板、公告、日历、展开／紧凑切换、系统主题与时区跟随、刷新与缓存，最终提供自带运行时的便携 ZIP。开发分为四个 milestone，每个阶段交付可运行版本，完成阶段内验证后暂停，由用户检查并明确同意后进入下一阶段。

本计划依据 [需求文档](requirements.md)、[技术设计](technical-design.md) 和 [视觉规范](design/visual-spec.md)。通知、自启动、历史筛选、备用数据源、ARM64 和安装包保留为后续工作。

## M1 界面与时间行为原型

目标是尽早检查小组件的大小、布局与时间语义，避免到真实数据接入后才发现展示方式不符合预期。

开发内容：

1. 检查开发环境，选定受支持的 .NET LTS 并锁定 SDK；建立 WPF 应用与测试项目，按架构目录组织代码。
2. 建立事件、快照和公告板状态模型，实现可注入时钟、状态判断与系统时区读取。
3. 使用模拟数据实现公告板、公告和日历的基本布局，包含深浅色、展开态和紧凑态；先实现查看所需的最小交互。
4. 提供演示入口，覆盖未来预告、到点、时间未定、无预告、预告消失、缓存／错误、长公告和同日多事件。演示数据显著标注，使用独立目录，不写入正式缓存。
5. 提供跨时区演示，覆盖 UTC+08:00、UTC+05:30 和使用夏令时的地区。演示可注入时区，不需要修改电脑设置；正常运行仍读取系统时区。

阶段内验证：用固定时钟验证倒计时、到点切换、目标更正与预告消失；验证同一绝对时刻在不同时区的显示、跨日分组和夏令时转换。在本机实际打开两种布局与两种主题，检查长文本及窗口最小工作区。

交付：可运行的演示便携包、演示场景操作说明、界面截图及已执行的验证结果。演示包也自带运行时，方便直接检查。

用户检查清单：

- [ ] 展开态的三个区域层级、大小和密度符合预期。
- [ ] 紧凑态适合长期摆放，信息仍清楚可读。
- [ ] 到点前显示“距公告预计时间”；到点后显示“最近公告的预计重置时间”，没有个人重置成功的暗示。
- [ ] 转换后的日期、时间和时区标签易于理解。
- [ ] 无明确时间、离线和长公告等状态不会破坏布局。

**暂停点：提交 M1 结果，请用户检查展示与时间行为。通过后进入 M2。**

## M2 真实数据与离线运行

目标是让小组件可以读取真实数据并在网络不稳定时继续使用。

开发内容：

1. 重新核对实际 API 合约与响应头，实现 DTO 校验、规范化转换、未知类型和可空字段处理。
2. 实现状态请求、历史顺序分页、按来源和 ID 合并；将真实数据接入 M1 的 ViewModel。
3. 实现状态每 5 分钟、历史每 30 分钟的默认调度及手动刷新；加入取消、请求序号、条件请求、限流与退避，避免迟到结果覆盖新数据。
4. 实现带版本的 JSON 缓存、原子写入、启动恢复和损坏文件处理；保留最近预告上下文及到点后的预计时间。
5. 分别展示状态与历史的数据健康信息，提供来源链接、最后成功检查时间和历史加载提示。

阶段内验证：通过假数据源验证分页重复、未知字段、304 无对应缓存、429、取消和乱序；验证首次离线、已有缓存离线、损坏缓存及缓存写入失败。真实联网验证接口转换和公告对应关系；未能现场发生的到点情形继续使用模拟数据验证。

交付：真实数据试用便携包、刷新／离线操作说明、接口验证与关键测试结果。模拟入口仍可用于复现，但与正式数据明确区分。

用户检查清单：

- [ ] 公告板时间、类型、公告原文与链接对应同一个事件。
- [ ] 日历按本地公告／观察日期归档；预计时间与公告发布时间区分清楚。
- [ ] 手动刷新反馈清楚，更新不会打断正在阅读的公告。
- [ ] 离线和接口失败时内容可读，缓存与错误提示不会被理解为新的预告。
- [ ] 到点或预告消失后仍保留有依据的时间信息；新预告到来后正确替换。

**暂停点：提交 M2 结果，请用户使用真实数据检查。通过后进入 M3。**

## M3 桌面功能完整版本

目标是完成第一版的桌面使用体验，并验证系统变化时的行为。

开发内容：

1. 完成公告前后切换、历史事件阅读、返回最新、日历导航、返回本月、当天多事件列表和原文外链。
2. 完成两种窗口模式切换及阅读位置保留；保存窗口模式、展开尺寸、位置和置顶设置。
3. 完成系统主题热切换、手动主题和高对比度回退；验证 Mica 可用时的效果并提供实色回退。
4. 完成系统时区、时钟和休眠恢复响应；重新转换所有时间与日历分组，保持阅读对象。
5. 完成拖动、可选置顶、托盘、显示／隐藏和显式退出。采用关闭收进托盘的初始实现，首次使用时说明；用户可在本阶段检查中调整此行为。
6. 隐藏或最小化时停止秒级界面更新，后台保留刷新；恢复时重新计算。退出时取消任务并清理订阅与托盘。

阶段内验证：检查 100%、150%、200% 缩放、小工作区、六行月历、键盘操作和长公告；测试系统主题与时区变更、休眠跨过预计时间、模式切换、关闭与退出、位置恢复和显示器断开后的窗口修正。实际多屏测试依赖可用设备，未覆盖的环境写入验证记录。

交付：完整功能试用便携包、设置与桌面操作说明、桌面验证记录及已知问题清单。

用户检查清单：

- [ ] 日历选择历史事件时，顶部公告板继续显示当前公告信息。
- [ ] 紧凑／展开、主题切换和刷新后，阅读选择与可见月份符合预期。
- [ ] 系统时区改变后显示随之更新，剩余时长保持一致。
- [ ] 长期摆放时，位置、大小、置顶与托盘操作顺手。
- [ ] Win+D 遵循普通窗口行为，恢复窗口后时间正确。

**暂停点：提交 M3 结果，请用户在日常桌面环境检查。通过后进入 M4。**

## M4 便携发布候选版

目标是形成可交付的第一版，并核对完整验收要求。

开发内容：

1. 修复前三个阶段检查中留下的问题；核对需求文档的全部验收标准。
2. 生成 Windows x64 自包含发布目录并打包 ZIP，包含项目许可、所需依赖声明和简明使用说明。
3. 检查用户数据路径、日志上限、缓存版本和升级兼容；明确退出后解压新版到新目录的升级步骤及移除方法。
4. 验证正式启动默认使用真实数据，演示模式仅通过显式入口启用。
5. 执行适用的自动测试、发布构建和最终桌面验证；在未安装 .NET 运行时的干净 Windows 11 x64 环境检查解压启动及升级。

交付：发布候选 ZIP、版本标识、使用与升级说明、完整验收记录、已知问题及未验证环境。若没有可用的干净 Windows 环境，保留该项为“待验证”，由用户或可用测试环境完成后才能宣称此项通过。

用户检查清单：

- [ ] 完整解压后直接运行，启动流程清楚。
- [ ] 升级至新版后保留兼容的设置与缓存。
- [ ] 第一版功能、文案、界面和桌面行为符合预期。
- [ ] 验收记录覆盖关键边界，未验证项已明确列出。

**暂停点：提交 M4 发布候选版，等待用户最终验收。通过后记录第一版完成；后续增强另行安排。**

## 每次阶段交付的记录

每个阶段在 `docs/milestones/` 保存检查记录，运行包建议放在 `artifacts/milestones/`；大体积生成物不提交到版本库。记录包括版本与构建方式、启动路径、可检查的场景、已执行验证、已知问题、用户反馈和阶段结论。

计划状态采用“未开始 → 开发中 → 待用户检查 → 已通过”，需要调整时记录“修改中”。技术检查通过后仍需等待用户确认，才能将阶段标为已通过。运行包必须与记录中的版本对应。

首次开发从 M1 开始。阶段工期在工程初始化和接口验证后依据实际进展评估；本计划先确定交付顺序与检查点，不设置缺乏依据的完成日期。
